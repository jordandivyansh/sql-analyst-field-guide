Module 07 · DBMS Concepts

Understand what happens beneath a query.

The interview goal is not database administration. It is explaining how data is modelled, kept correct, read concurrently and made fast.

NormalizationACIDIndexesOLTP vs OLAP

Database → DBMS → relational database

Database
An organized collection of persistent data.
DBMS
Software that stores, retrieves, secures, recovers and coordinates access to data.
RDBMS
A DBMS that represents data as related tables and enforces relational rules.
Schema
The logical blueprint: tables, columns, relationships, constraints and other objects.
Instance
The actual data stored at a particular moment.
Interview lineMySQL is an RDBMS; SQL is the language used to communicate with it.

Entity–relationship modelling

Entity

A business object such as Customer, Order or Product.

Attribute

A property such as order_date or price.

Relationship

One-to-one, one-to-many, or many-to-many; the last needs a bridge table.

customers (customer_id PK, customer_name)
orders    (order_id PK, customer_id FK, order_date)
products  (product_id PK, product_name)
order_items (order_id FK, product_id FK, quantity,
             PRIMARY KEY (order_id, product_id))

State the grain first: one row in order_items represents one product line within one order.

Functional dependency and normalization

If A → B, a value of A determines one value of B. Normalization uses dependencies to reduce duplication and update anomalies.

FormRuleProblem removed
1NFAtomic values; no repeating groupsLists packed into one cell
2NF1NF + every non-key attribute depends on the whole composite keyPartial dependency
3NF2NF + non-key attributes do not depend on other non-key attributesTransitive dependency
BCNFEvery determinant is a candidate keySome anomalies left by 3NF
Denormalization is a trade-offAnalytics systems may intentionally duplicate or pre-aggregate data for simpler, faster reads. Document the source of truth and refresh logic.

Transactions and ACID

Atomicity

All steps commit or none do.

Consistency

A transaction moves the database between valid states.

Isolation

Concurrent transactions behave according to a defined visibility level.

Durability

Committed changes survive failure.

START TRANSACTION;
UPDATE accounts SET balance = balance - 500 WHERE account_id = 1;
UPDATE accounts SET balance = balance + 500 WHERE account_id = 2;
COMMIT; -- use ROLLBACK if either step fails

Concurrency anomalies and isolation

AnomalyWhat happens
Dirty readRead data another transaction has not committed.
Non-repeatable readRe-reading one row gives a changed value.
Phantom readRe-running a range query returns added/removed rows.
Lost updateOne write overwrites another concurrent write.

Lower isolation

More concurrency, fewer protections. READ UNCOMMITTED is weakest.

Higher isolation

More predictable results, with possible blocking/retry costs. SERIALIZABLE is strongest.

InnoDB also uses multi-version concurrency control (MVCC) so many reads can view a consistent snapshot without blocking writers.

Indexes: a faster route to rows

A B-tree index keeps keys ordered and points to rows/pages. It can accelerate selective equality, range, join and ordering operations—but costs storage and write work.

CREATE INDEX idx_orders_customer_date
  ON orders (customer_id, order_date);
  • The composite index naturally supports customer_id and customer_id + order_date.
  • It usually does not efficiently support order_date alone: the leftmost-prefix rule.
  • A covering index contains every column a query needs, reducing table lookups.
  • Low-selectivity columns such as a two-value flag are often weak standalone indexes.
Sound interview answerDo not say “index every filter column.” Say you will examine workload, selectivity, column order, write cost, and the execution plan.

Locks, deadlocks and recovery

Locks coordinate conflicting access. A deadlock occurs when transactions wait cyclically; the database detects it and rolls one back. Keep transactions short, touch objects in a consistent order, index lookup paths, and retry safely.

Write-ahead log

Records changes before pages are finalized.

Checkpoint

Limits how far recovery must replay.

Backup + restore test

A backup is useful only if recovery is verified.

In a star schema, a numeric fact table connects directly to descriptive dimensions. A snowflake normalizes dimensions further. ETL transforms before loading; ELT loads first and transforms in the analytical platform.
