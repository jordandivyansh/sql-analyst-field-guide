Project A · Data Analyst

Life Sciences Commercial Performance Command Center

4 weeks

Question: Where are brand performance, HCP engagement and territory execution diverging—and what should commercial leadership prioritize next month?

Users

Sales leadership, brand team, field operations.

Stack

MySQL, Python/Pandas, Power BI, GitHub.

Data

Synthetic, non-patient, clearly documented commercial data.

Model

fact_sales(date_id, territory_id, product_id, units, net_sales)
fact_calls(date_id, territory_id, hcp_id, product_id, call_id, channel)
dim_date(date_id, date, month, quarter)
dim_territory(territory_id, region, manager)
dim_product(product_id, brand, indication)
dim_hcp(hcp_id, specialty, segment)

Required analysis

  • Month-over-month and year-over-year growth with complete-date logic.
  • Actual vs target by region, territory and brand.
  • HCP reach, frequency and channel mix; separate activity from effectiveness.
  • Territory contribution, Pareto concentration and underperformance flags.
  • Data-quality checks for duplicate calls, missing dimensions and impossible values.

Portfolio deliverables

  1. Business brief and metric dictionary with owner, formula, grain and caveats.
  2. DDL, seed/synthetic-data script and 15–20 annotated analytical queries.
  3. Power BI report: Executive, Territory, HCP Engagement and Data Quality pages.
  4. README with schema diagram, screenshots, three recommendations and limitations.
  5. Automated checks comparing totals before/after joins and SQL vs dashboard.
AI integration with proofUse an LLM to propose anomaly hypotheses or draft query tests, but store the prompt, verify generated SQL against known totals, and document every rejected suggestion. The skill demonstrated is AI-assisted analysis with human validation.

Resume bullets—use only after you can defend the numbers

  • Built a MySQL and Power BI commercial analytics solution across sales, territory and HCP engagement data, defining governed KPIs and drill-down views for monthly performance review.
  • Implemented SQL quality controls and AI-assisted anomaly triage, validating join cardinality and metric reconciliation before surfacing commercial recommendations.
Project B · Business Analyst

Sales Incentive Change & Approval Workflow

3 weeks

Problem: Incentive-plan changes arrive through email and spreadsheets, creating unclear ownership, approval delays, configuration errors and weak auditability.

Users

Sales ops, compensation analysts, finance, compliance, IT.

Tools

Process map, BRD, user stories, SQL, dashboard mockup.

Outcome

A traceable future-state workflow and measurable UAT plan.

Discovery and scope

  • Create stakeholder map and RACI; prepare role-specific interview questions.
  • Map the as-is process, handoffs, wait states, rework loops and control gaps.
  • Baseline cycle time, first-pass acceptance, rework rate and SLA breaches.
  • Define in/out of scope, assumptions, risks and dependencies.

Future-state requirements

IDUser storyExample acceptance criterion
US-01As a compensation analyst, I want a validated change form.Given missing effective date, submission is blocked with a field-level message.
US-02As an approver, I want plan deltas and financial impact together.Approval view shows previous/new values and calculated impact.
US-03As compliance, I need an immutable decision history.Every status transition records actor, timestamp, reason and version.
US-04As sales ops, I want SLA alerts.Owner receives escalation when a stage exceeds its configured threshold.

Data and control layer

SELECT request_id, stage, owner_id,
       TIMESTAMPDIFF(HOUR, entered_stage_at, NOW()) AS age_hours
FROM change_requests
WHERE status = 'open'
  AND TIMESTAMPDIFF(HOUR, entered_stage_at, NOW()) > sla_hours;

Portfolio deliverables

  1. One-page charter, stakeholder/RACI matrix and as-is/to-be process maps.
  2. BRD with functional/non-functional requirements and business rules.
  3. Prioritized backlog, acceptance criteria and requirements traceability matrix.
  4. Low-fidelity workflow/dashboard prototype plus data dictionary.
  5. UAT plan: scenarios, test data, expected results, severity and sign-off.
  6. Change plan: communication, training, pilot, adoption metrics and rollback.

Success metrics

Target a 30% shorter median cycle time, 25% fewer rework loops, ≥95% SLA compliance and 100% auditable approvals. Label these as project targets, never fabricated realized impact.

Resume bullets—after artifacts and test results exist

  • Designed an end-to-end sales incentive change workflow, translating stakeholder needs into a BRD, process maps, prioritized user stories, acceptance criteria and traceable UAT scenarios.
  • Defined SLA and quality metrics with SQL exception reporting, proposing controls for version history, approval auditability and change adoption.
