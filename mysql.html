Know the dialect you will actually write.

Most SQL ideas transfer across databases. This page marks the MySQL syntax and engine details interviewers expect you to recognize.

MoneyDECIMAL(12,2)Avoid binary floating-point for exact amounts

CREATE TABLE orders (
  order_id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  customer_id BIGINT UNSIGNED NOT NULL,
  order_total DECIMAL(12,2) NOT NULL,
  ordered_at DATETIME NOT NULL,
  status VARCHAR(30) NOT NULL,
  INDEX idx_customer_date (customer_id, ordered_at)
) ENGINE = InnoDB;

NULL: IFNULL vs COALESCE

-- MySQL-specific, exactly two arguments
IFNULL(referee_id, 0)

-- SQL-standard, first non-NULL from two or more expressions
COALESCE(referee_id, backup_referee_id, 0)

For “not referred by customer 2,” the clearest predicate is often:

WHERE referee_id <> 2 OR referee_id IS NULL;

Replacing NULL with 0 is correct only if 0 cannot be a meaningful ID.

Date and time patterns

-- Half-open range is safe for DATETIME values
WHERE ordered_at >= '2026-01-01'
  AND ordered_at <  '2026-02-01';

SELECT
  DATE_FORMAT(ordered_at, '%Y-%m') AS order_month,
  TIMESTAMPDIFF(DAY, ordered_at, shipped_at) AS ship_days,
  DATE_ADD(ordered_at, INTERVAL 30 DAY) AS due_at
FROM orders;
SargabilityYEAR(ordered_at) = 2026 may prevent an index range scan. Prefer explicit lower and upper bounds.

Execution plans with EXPLAIN

EXPLAIN ANALYZE
SELECT customer_id, SUM(order_total) AS revenue
FROM orders
WHERE ordered_at >= '2026-01-01'
  AND ordered_at <  '2027-01-01'
GROUP BY customer_id;

Inspect

Access type, possible/selected key, estimated vs actual rows, loops, sorting and temporary work.

Improve

Reduce rows early, make predicates indexable, fix join keys, then test an index that matches the workload.

A full table scan is not automatically bad: for a small table or a query returning most rows, it may be cheapest.

InnoDB, transactions and autocommit

InnoDB is MySQL’s default transactional engine, supporting ACID transactions, row-level locking, foreign keys and MVCC. MySQL commonly starts with autocommit = 1, so each standalone statement commits unless you begin a transaction.

START TRANSACTION;
SELECT quantity FROM inventory WHERE product_id = 42 FOR UPDATE;
UPDATE inventory SET quantity = quantity - 1 WHERE product_id = 42;
COMMIT;

SQL modes and grouping

With ONLY_FULL_GROUP_BY, selected non-aggregate expressions must be functionally dependent on the grouped columns. This catches ambiguous queries.

-- Invalid/ambiguous when a customer has many orders
SELECT customer_id, order_date, SUM(order_total)
FROM orders
GROUP BY customer_id;

-- State the intended grain
SELECT customer_id, MAX(order_date) AS latest_order,
       SUM(order_total) AS lifetime_value
FROM orders
GROUP BY customer_id;
