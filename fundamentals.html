Module 01 · Foundations

Know what the database is doing.

The syntax becomes easier when tables, keys, constraints, NULL and logical query processing form one mental model.

BeginnerInterview essential30–45 min

Database, DBMS, RDBMS, SQL

Database
An organized collection of data.
DBMS
Software that stores, retrieves, secures and coordinates access to databases.
RDBMS
A DBMS based on related tables, constraints and relational operations. MySQL and PostgreSQL are examples.
SQL
The declarative language used to define, query and manipulate relational data.
Interview distinctionMySQL is the database management system. SQL is the language. A query states what result you want; the optimizer chooses much of how to obtain it.

The relational model

Relation / table

A set-like collection of rows describing one entity or event type.

Tuple / row

One record at the table’s declared grain.

Attribute / column

A named property with an intended domain and data type.

Always state the grain“One row per order” prevents incorrect joins and aggregations more effectively than memorizing syntax.

Keys and constraints

ConceptPurposeInterview point
Primary keyUniquely identifies each row; cannot be NULL.One per table, possibly composite.
Candidate keyAny minimal column set capable of unique identification.One candidate is chosen as primary.
Foreign keyReferences a key in another or the same table.Maintains referential integrity.
UNIQUEPrevents duplicate values or combinations.NULL treatment varies by DBMS.
NOT NULL / CHECKEnforces required and valid values.Prefer database guarantees for critical rules.
CREATE TABLE orders (
  order_id     BIGINT PRIMARY KEY,
  customer_id  BIGINT NOT NULL,
  order_date   DATE NOT NULL,
  status       VARCHAR(20) DEFAULT 'pending',
  amount       DECIMAL(12,2) CHECK (amount >= 0),
  CONSTRAINT fk_customer
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

NULL and three-valued logic

NULL means missing or unknown—not zero and not an empty string. Comparisons with NULL produce UNKNOWN, while WHERE keeps only TRUE rows.

-- Wrong: never true
WHERE referee_id = NULL

-- Correct
WHERE referee_id IS NULL

-- Include non-2 values and missing values
WHERE referee_id <> 2 OR referee_id IS NULL

-- Standard replacement function
SELECT COALESCE(discount, 0) FROM orders;

COUNT(*)

Counts rows, including rows containing NULLs.

COUNT(column)

Counts only non-NULL values in that column.

Logical query-processing order

The written order is not the logical evaluation order.

StepClauseWhat happens
1FROM / JOINBuild the working row set.
2WHEREFilter individual rows.
3GROUP BYCreate groups.
4HAVINGFilter groups.
5SELECTCalculate output expressions.
6DISTINCTRemove duplicate output rows.
7ORDER BYSort the result.
8LIMITReturn a subset.
Why aliases sometimes fail in WHEREA SELECT alias is logically created after WHERE. Use the underlying expression, a subquery, or a CTE.
