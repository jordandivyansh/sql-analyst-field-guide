Module 02 · Query craft

Shape raw rows into useful answers.

Selection, filtering, transformation, dates and strings are the vocabulary of almost every analyst query.

Core SQLSQL 50 ready45–60 min

SELECT deliberately

SELECT
  order_id,
  customer_id,
  amount,
  amount * 0.18 AS tax_amount
FROM orders;
Avoid SELECT * in production analysisExplicit columns make grain clearer, reduce data transfer, survive schema changes better, and prevent duplicate column-name confusion after joins.

Filtering operators

Comparison

=, <>, >, >=, BETWEEN

Membership

IN (...), NOT IN (...)

Pattern

LIKE 'A%', LIKE '_at'

Logical

NOT → AND → OR; use parentheses.

SELECT order_id, amount
FROM orders
WHERE order_date >= '2026-01-01'
  AND status IN ('paid', 'shipped')
  AND amount BETWEEN 500 AND 5000;
NOT IN + NULL trapIf the subquery or list contains NULL, NOT IN can return no rows because comparisons become UNKNOWN. Prefer NOT EXISTS for anti-joins.

CASE: business rules inside a query

SELECT
  customer_id,
  lifetime_value,
  CASE
    WHEN lifetime_value >= 100000 THEN 'Platinum'
    WHEN lifetime_value >= 50000  THEN 'Gold'
    WHEN lifetime_value >= 10000  THEN 'Silver'
    ELSE 'Standard'
  END AS customer_tier
FROM customers;

CASE stops at the first true condition. Order overlapping conditions from most specific/highest threshold to least specific.

Dates and period boundaries

SELECT
  order_id,
  order_date,
  YEAR(order_date) AS order_year,
  DATE_FORMAT(order_date, '%Y-%m') AS order_month,
  DATEDIFF(CURRENT_DATE, order_date) AS days_since_order
FROM orders
WHERE order_date >= '2026-01-01'
  AND order_date <  '2026-02-01';
Prefer half-open intervals>= start AND < next_period works cleanly for DATE and timestamp values. BETWEEN is inclusive at both ends and can accidentally exclude late-day timestamps.

Type conversion and defensive math

SELECT
  CAST(raw_amount AS DECIMAL(12,2)) AS amount,
  revenue / NULLIF(order_count, 0) AS average_order_value,
  COALESCE(discount, 0) AS discount
FROM monthly_metrics;

NULLIF(x, 0) turns a zero denominator into NULL, preventing a divide-by-zero failure while signaling “not computable.”

Sorting, limiting and deterministic results

SELECT customer_id, lifetime_value
FROM customers
ORDER BY lifetime_value DESC, customer_id ASC
LIMIT 10;

Without ORDER BY, row order is not guaranteed. Add a stable tie-breaker when selecting “top N.”
